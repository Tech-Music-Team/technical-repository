Relatório de Correções — Docker Compose & ETL

Documentação das correções aplicadas para funcionamento correto do ambiente containerizado.

Projeto: Tech Music Team Data: 25/04/2026 Autor: Jorge Luiz 3 problemas corrigidos
Contexto

Visão Geral do Ambiente

O projeto utiliza Docker Compose para orquestrar três serviços: a aplicação web (app), o banco de dados MySQL (db) e o ETL em Java (jar). O serviço jar é responsável por baixar arquivos do S3 (AWS Academy) e inserir os dados no banco MySQL.

Ao executar docker-compose up --build, três problemas foram identificados nos logs que impediam o ETL de funcionar corretamente.

Problema 1

URL de Conexão Hardcoded

leitura-dados/src/main/java/school/sptech/repository/ConexaoBanco.java
Causa A URL de conexão com o banco estava fixada no código como localhost:3307. Dentro do Docker, cada serviço possui sua própria rede isolada — o container jar não enxerga o banco como localhost, mas sim pelo nome do serviço definido no compose (db). A porta interna do MySQL dentro da rede Docker é 3306, não 3307 (que é apenas o mapeamento para o host).
Erro nos logs Erro ao gravar log no banco de dados: Failed to obtain JDBC Connection

Antes

String url      = "jdbc:mysql://localhost:3307/tech_music";
String username = "root";
String password = "p0o9i8u7";

Depois

String host     = System.getenv().getOrDefault("DB_HOST",     "localhost");
String port     = System.getenv().getOrDefault("DB_PORT",     "3307");
String database = System.getenv().getOrDefault("DB_DATABASE", "tech_music");
String url      = "jdbc:mysql://" + host + ":" + port + "/" + database;
String username = System.getenv().getOrDefault("DB_USER",     "root");
String password = System.getenv().getOrDefault("DB_PASSWORD", "p0o9i8u7");
Explicação System.getenv().getOrDefault("VARIAVEL", "fallback") lê a variável de ambiente injetada pelo Docker Compose. Se não existir (rodando localmente), usa o valor padrão. Assim o mesmo código funciona em ambos os ambientes.
Problema 2

Race Condition — Jar iniciando antes do MySQL estar pronto

Tech_Music_Team/docker-compose.yaml
Causa O depends_on: - db padrão do Docker Compose apenas aguarda o container do MySQL iniciar — não garante que o MySQL dentro dele esteja pronto para aceitar conexões. O MySQL leva alguns segundos para inicializar, criar o banco e executar os scripts DDL/DML. O serviço jar subia imediatamente e tentava conectar nesse intervalo, falhando.

Antes

jar:
  depends_on:
    - db
  build: ../leitura-dados

Depois

db:
  image: mysql:8.0
  healthcheck:
    test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-pp0o9i8u7"]
    interval: 10s     # testa a cada 10 segundos
    timeout: 5s      # desiste se demorar mais de 5s
    retries: 5       # tenta 5 vezes antes de marcar como unhealthy
    start_period: 30s # aguarda 30s antes de começar a contar

jar:
  depends_on:
    db:
      condition: service_healthy   # só sobe quando o healthcheck passar
  build: ../leitura-dados
Explicação O healthcheck faz o Docker testar periodicamente se o MySQL está respondendo via mysqladmin ping. Apenas quando esse teste passar (MySQL realmente pronto), o condition: service_healthy libera o container jar para subir.
Problema 3

Credenciais AWS não passadas ao container

Tech_Music_Team/docker-compose.yaml
Causa O serviço jar acessa o S3 da AWS Academy, mas as credenciais não estavam sendo injetadas no container. O SDK da AWS tenta encontrar credenciais em várias fontes (variáveis de ambiente, arquivo de perfil, EC2 metadata...) e não encontrou nenhuma.
Erro nos logs Unable to load credentials from any of the providers in the chain AwsCredentialsProviderChain...
Atenção — AWS Academy A AWS Academy utiliza credenciais temporárias com duração limitada (~4 horas). Além de AWS_ACCESS_KEY_ID e AWS_SECRET_ACCESS_KEY, é obrigatório passar o AWS_SESSION_TOKEN.

Adicionado ao docker-compose.yaml (serviço jar)

jar:
  environment:
    DB_HOST: db
    DB_PORT: 3306
    DB_DATABASE: tech_music
    DB_USER: root
    DB_PASSWORD: p0o9i8u7
    AWS_ACCESS_KEY_ID: ${AWS_ACCESS_KEY_ID}
    AWS_SECRET_ACCESS_KEY: ${AWS_SECRET_ACCESS_KEY}
    AWS_SESSION_TOKEN: ${AWS_SESSION_TOKEN}
    AWS_REGION: ${AWS_REGION:-us-east-1}
Explicação A sintaxe ${VARIAVEL} faz o Docker Compose ler o valor do terminal do host e injetar no container. As credenciais nunca ficam salvas no código — ficam apenas na sessão do terminal de quem executa o compose.
Como Rodar

Passo a Passo para Executar o Ambiente

As credenciais da AWS Academy ficam disponíveis no painel do Learner Lab em AWS Details → AWS CLI.

1
Abrir o PowerShell na pasta do projeto 
cd Tech_Music_Team
2
Exportar as credenciais AWS no terminal 
$env:AWS_ACCESS_KEY_ID     = "ASIA..."
$env:AWS_SECRET_ACCESS_KEY = "abc123..."
$env:AWS_SESSION_TOKEN     = "FwoG..."
3
Subir o ambiente 
docker-compose up --build
Lembrete As credenciais da AWS Academy expiram a cada ~4 horas. Sempre que isso acontecer, repita o passo 2 com as novas credenciais e execute docker-compose up --build novamente.
